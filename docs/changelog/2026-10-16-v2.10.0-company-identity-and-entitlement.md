# v2.10.0 — Company identity, audience entitlement declaration, invitation correlation

Status: prepared locally; publication and release-mirror verification pending.

All four core SDKs expose the canonical company identity a consumer persists, the required
audience-entitlement declaration an environment is created with, the invitation acceptance linkage,
and the human-owner company-binding operation. Existing client constructors are unchanged.

- `companyUuid` — required nullable UUID string on the project summary and environment status.
  It is the persisted, immutable public company identity; `null` means the project is explicitly
  unbound. Never infer it from a slug, an email, a membership or the caller's own company, and never
  substitute a storage-namespace identifier for it.
- `audienceEntitlementMode` — required on project creation and on environment creation, with the two
  named values `organisation_membership` and `explicit_grants`. The caller declares how an environment
  admits an audience: `organisation_membership` admits any live member of the organisation for every
  registered audience, while `explicit_grants` admits an audience only when the principal holds a grant
  for that exact audience. It is immutable after creation, so a deny can never revert to permissive.
- `bindProjectCompany` / `BindProjectCompany` / `bind_project_company` — binds an explicitly unbound
  historical project to the authenticated human owner's company and returns
  `{projectId, companyUuid}`. It is the actionable step a `company_binding_required` refusal names:
  the body is empty, a machine credential and a foreign rebind are refused, and repeating it for the
  same company is safe, so it carries no idempotency key.
- `acceptedPrincipalId` — nullable UUID string on invitation reads and the issuance replay receipt,
  taken only from Custd's own recorded acceptance linkage. Absent or `null` means unavailable,
  including historical accepted invitations; never match the email to guess a principal.
- `CheckApplicationAuthority` (Go) and `checkApplicationAuthority` (PHP) — the application's online
  authority decision, sent with the application credential alone and never the platform machine token.
  An HTTP 200 that denies stays a denial; a malformed success is an error rather than positive evidence.

The shared version and SDK identity constants are `2.10.0`. Consumers must use the published GitHub
release once its mirrors are verified, not a local filesystem replacement.
