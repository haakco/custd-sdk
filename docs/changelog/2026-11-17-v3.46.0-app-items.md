# v3.46.0 — app items

Adds the SDK half of hosted app items: link access, signed-in ownership, measurements, uncertainty models and
self-refreshing reads.

- **App items client (JS).** `AppItemsClient`, on `app.appItems` when the discovery file enables `app_data` or from
  `AppItemsClient.fromDiscovery`, covers `/api/v1/app/items` and every `/api/v1/app/item` route (read, settings,
  measurements, CSV, estimates, complete, cancel, reopen, dashboard entries, link revoke and rotate) and the
  `/api/v1/app/forecast` runs, latest, run and story routes. Typed DTOs match the JSON names; failures are
  `AppItemError` with the server's problem `code` and `fieldErrors`. Link tokens travel only in `Authorization`.
- **Signed-in ownership (JS).** With a `userToken` provider (the hosted app wires its `BrowserSignIn`), every call
  also sends `X-Custd-User-Token`. `listMyItems()` reads "my items", `claim(ownerToken)` takes ownership (409
  `claimed` when another user owns it), and `{ item }` in place of a token reaches an owned item with no link. Item
  reads carry `ownership` (`unowned`, `yours`, `other`). `AppItemError.signInNeeded` marks `app_user_refused` and
  `app_sign_in_required`; `app_user_check_unavailable` is retryable and keeps the session.
- **Uncertainty models (JS/React).** Model item DTOs, `addModelVersion`, `copyModel`, `runModel`, `latestModelRun`,
  `watchLatestModelRun` and `calculateModel` (`POST /api/v1/app/models/calculate`, any link, never stored, 429
  `app_model_calculate_limited`). Model and latest-run reads carry `queuedRunFailure`. React: `ModelEditor` (inline
  errors from the server's `fieldErrors`, a cycle marks each quantity in it), `ModelCalculator` (calculates through
  the client by default and shows a failed queued run), `QuantityHistogram`, `SensitivityView`, `MeasureNextPanel`,
  `SafeMarkdown`, `downloadSummaryCsv`, the value shorthand helpers and `useAppModelRun`.
- **Hosted app start (JS).** Tracking takes `identityMode` and `allowedOrigins` from the discovery file and skips the
  Site config fetch when both are present; it still fetches them from an older backend. Sign-out defaults to the
  discovery `signIn.postLogoutRedirectUri`.
- **Conditional polling (JS).** `watchItem`, `watchLatestForecast` and `watchForecastStory` poll with `If-None-Match`
  (default 5 s), pause in hidden tabs, back off on failures and report `loading`, `fresh`, `empty`, `stale`,
  `offline` or `error` with the last confirmed time. One poller per read and link; writes refresh that link's watchers.
- **Live hooks (React).** `useAppItem`, `useAppForecast` and `useAppForecastStory` over those pollers, through
  `CustdHostedAppProvider` or an explicit client.
- **Link helpers (JS).** `appItemOwnerUrl` (`https://<host>/edit/<kindPath>#<ownerToken>`), `appItemShareUrl`
  (`https://<host>/<kindPath>/<shareToken>`) and `parseAppItemLink` for a pasted link or bare token.
- **Hosting removal receipts (Go).** `AuthProjectEnvironmentOffboarding.Hosting` is an
  `AuthEnvironmentHostingWithdrawal` (status, withdrawn releases, Sites and alerts);
  `AuthProjectEnvironmentDeletion.Hosting` is an `AuthEnvironmentHostingRemoval` (releases, objects, Sites, items,
  links and alerts removed); `AuthProjectDeletion.Hosting` lists one `AuthProjectHostingRemoval` per environment. New
  problem codes `AuthProjectHostingRemovalIncompleteCode` (`hosting_removal_incomplete`, repeat the delete) and
  `AuthProjectEnvironmentDeletingCode` (`environment_deleting`, 409 on a release write during a delete).

`@haakco/custd-react` now requires `@haakco/custd-sdk` 3.46.0 or newer.
