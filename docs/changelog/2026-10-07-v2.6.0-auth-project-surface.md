# v2.6.0 Auth-project surface

Every SDK can now administer Custd's application identity boundary: create and
list projects, create an environment, apply and read back an environment's
desired state including its audience binding, and manage an application
principal's sessions and membership. Until now a consumer holding a published
client library could not do any of it, which is the gap that made the published
consumer contract unusable in practice.

- New auth-project surface in all four languages: `client.Admin.AuthProjects`
  in Go, `client.admin.authProjects` in JavaScript, `client.admin.auth_projects`
  in Python, and `client->adminAuthProjects()` in PHP. It exposes create and
  list projects, create an environment, apply / preview / status for an
  environment's desired state, list a principal's sessions, revoke one session,
  revoke all of them, and revoke a membership.
- The audience binding is readable rather than inferable. `status` returns the
  applied desired state and the environment it belongs to, so a consumer reads
  back the `(project, environment, audience)` mapping it applied and, once
  registration has run, the derived provider client ids.
- The derived `custd-app-<environmentId>-<audienceSlug>` and
  `custd-group-<environmentId>-<audienceSlug>` values are deliberately not
  fields: the service does not return them and the contract defines them as
  derived. A shared client does not carry consumer-specific knowledge.
- A machine caller names the platform user it acts for through an explicit
  option on every call, so it cannot be sent by accident, and a human
  administrator's own token subject is never overridden.
- Retry-safe writes require an idempotency key and refuse a missing one locally
  instead of spending a round trip on a guaranteed `400`. The served apply
  operation requires the header even though the generated specification omits
  the parameter; the SDK follows the service.
- Every request and response boundary is a named type in each language. The
  desired-state document is nested and large, and a consumer building it from
  an untyped dictionary cannot tell a field it forgot from one the service
  ignores.
