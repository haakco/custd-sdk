# v2.7.0 — Application principal lifecycle

Status: prepared locally; publication and release-mirror verification pending.

All four core SDKs expose typed principal suspension, restoration, erasure and
export operations through their existing auth-project admin clients. Existing
client constructors are unchanged.

- Targets name the project, environment, directory and provider subject. Each
  path segment is escaped; Custd validates the owning boundary.
- Suspension withdraws authority before provider session revocation. Restoration
  retains enrolled factors and refuses pending suspension or erasure.
- Mutations require an idempotency key before transport. Erasure also requires
  explicit confirmation and covers the complete principal mapping set.
- Erasure receipts expose actual deletion counts. `countsRecorded: false` on a
  replay means the original counts are unavailable, not that nothing was erased.
- Export returns every public identity with its own completeness status and
  preserves JSON trait types. It contains no credential, code, token or session
  material. Incomplete or unavailable traits must not be shown as a complete
  export.

The shared version and SDK identity constants are `2.7.0`. Consumers must use the
published GitHub release once its mirrors are verified, not a local filesystem
replacement.
