# v2.6.1 Membership-revoke `reason` field removed

All four SDKs no longer accept a `reason` on the application-membership
revocation body. The Admin API accepted the field, length-validated it, and
then never carried it on the audit row, so it was dead surface: a caller could
state a cause that was silently discarded. The service and every SDK now drop
the field together.

- Go `ApplicationMembershipRevokeRequest`, TypeScript
  `ApplicationMembershipRevokeRequest`, Python
  `ApplicationMembershipRevokeRequest`, and PHP `MembershipRevokeRequest` no
  longer carry `reason`. The body is now the organisation alone; the project,
  environment, directory and provider subject already come from the address.
- **Breaking:** a caller that still passes `reason` is now rejected by the
  strict request boundary. Go and PHP fail to compile against the removed
  member, TypeScript rejects an excess object property, Python's typed request
  flags the unknown key, and the running service refuses the unknown JSON field
  with `400`. Update callers to omit the field; the audit row still records who
  acted, on which membership, and when.
- No other request or response shape changed, and idempotency requirements are
  untouched.
