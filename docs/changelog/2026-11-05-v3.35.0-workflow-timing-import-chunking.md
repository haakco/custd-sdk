# Workflow timing imports beyond one request

`AppendBatch` (Go) and `appendBatch` (PHP) now split an import into requests of
at most 10,000 observations or 1 MiB of encoded JSON, whichever comes first.

- Custd no longer refuses a run past a fixed lifetime fact count, so a retained
  consumer run that holds 2,076 facts can be imported whole. A run's history is
  preserved rather than discarded to fit a ceiling.
- A single import larger than one admin request used to fail with the server's
  body-cap answer, which reads as malformed JSON and names nothing actionable.
  The failure now names the input offset and states that earlier chunks may have
  committed, so the caller replays with the same idempotency keys instead of
  rewriting keys or dropping observations.
- Every returned result keeps its index relative to the caller's original input,
  so per-item rejections remain addressable across chunks.
- A response that does not account for every input in a chunk is an error rather
  than a silent partial success. `RequireAccepted` / `requireAccepted` still
  reports rejections across the whole import, not just the last chunk.
- A single observation that cannot fit one request is refused before any request
  is sent, rather than after earlier chunks committed.
