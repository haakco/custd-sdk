# v3.72.0 — machine access, request IDs everywhere, and signing in again from settings

## Features

- **Machine access, every SDK.** Read and set what a company's machine credentials may do, for the whole company
  and for one machine, and read one machine's effective access: Go `Admin.MachineAccess`, JS
  `admin.machineAccess`, React `useMachineAccess` and siblings, Python `client.admin.machine_access`, PHP
  `adminMachineAccess()`, Rust `get_machine_access` and siblings. Five operations: company get/update, machine
  override get/update, effective get.
- **Typed machine access refusals.** A `machine_access_blocked` or `machine_access_unavailable` refusal carries a
  typed `machineAccess` block (area, blockedBy, companySlug, clientId), so a CI log says exactly what to change.
- **Request IDs on every answer.** JS, Python, PHP and Rust now report the request ID the way Go does: on every
  refusal (the `X-Request-Id` header, else the envelope's `requestId`, else the problem's `traceId`) and through
  an ambient recorder on accepted answers.
- **Sign in again from hosted settings.** `BrowserSignIn.restore()` handles `custd_account=sign_in_again` from
  hosted settings: it signs in again and reopens settings.

## Changes

- OAuth client DTOs gain `createdAt`.
- `@haakco/custd-react` now needs `@haakco/custd-sdk` 3.72.0 or later.
- Python admin refusals use the server's `detail` as the message; 429 and 5xx report `bounded` retryability.
- PHP ingest refusals throw `AdminProblemException` (still a `RuntimeException`).
