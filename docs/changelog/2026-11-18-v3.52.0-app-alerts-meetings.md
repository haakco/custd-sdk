# v3.52.0 — app item alerts and meetings

Adds typed clients for app item alerts and meeting items, and brings the Rust crate up to the JS app items client.

- **Alerts (JS).** `AppItemsClient` covers `/api/v1/app/item/alerts`: `alertSettings`, `addAlertRule`,
  `removeAlertRule`, `addAlertWebhook` (the `signingSecret` is shown once), `removeAlertWebhook`, `alertDeliveries`,
  and for a signed-in user `subscribeAlertEmail` (`PUT …/subscription`) and `unsubscribeAlertEmail`. DTOs and
  `APP_ALERT_RULE_TYPES`, `APP_ALERT_CHANNELS`, `APP_ALERT_DELIVERY_OUTCOMES` and `APP_ALERT_ERROR_CODES` are exported
  from `@haakco/custd-sdk/browser`. `AppItemError.verifiedEmailNeeded` marks `app_alert_no_verified_email`;
  `app_alert_email_check_unavailable` is a retryable 503.
- **Meetings (JS/React).** `AppItemCreateRequest` takes `{ kind: "meeting", meeting: { name, blocks } }`;
  `startMeeting`, `advanceMeeting(access, { blockUuid })` and `endMeeting` return the item read, whose `meeting` holds
  the status, current block, each block's predicted, allocated (rebalanced) and actual time, and the summary. A
  repeated advance is a no-op 200; a stale one is 409 `APP_MEETING_ERROR_CODES.stepRefused`, after which the client's
  watchers poll at once. React: `useAppMeeting` reads it through the item's shared poller.
- **Rust.** `AppClient::with_user_token` sends `X-Custd-User-Token`; `list_my_items`, `owned_item(item_uuid)` (no
  link), `AppLink::claim`, `forecast_story`, meetings, alerts, `ApiError::code()`, and `read_hosted_app_discovery` (with
  `allowed_origins`) and `AppClient::from_discovery`. `AppItem` now carries `ownership` and `AppItemRead` a `meeting`. `AppItemCreate`
  derives `Default` and gains `meeting`; build it with `..AppItemCreate::default()`.

`@haakco/custd-react` now requires `@haakco/custd-sdk` 3.52.0 or newer.
