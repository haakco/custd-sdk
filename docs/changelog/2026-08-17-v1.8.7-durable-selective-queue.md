# Custd SDK v1.8.7

## Python — durable selective queue

The Python SDK now ships a crash-safe, file-backed event queue with selective
ack semantics. The change is Python-only in this release: PHP continues to ship
its own `FileQueueStore`, and the JS and Go SDKs retain their existing
in-memory queues (their queue work happens in their own repositories).

### What changed

- **Crash-safe file-backed queue (`FileQueueStorage`).** Queued events are
  persisted through an atomic private JSON replacement (`mkstemp` + `fsync` +
  directory `fsync` + `os.replace`), so event UUIDs survive a process restart
  or a power loss. The on-disk format is a plain JSON list of event envelopes;
  no external service is involved.
- **Stable UUID retention.** Each queue entry keeps its `eventUuid` across
  restarts. On reload, the queue is reconstructed byte-for-byte from the file
  and sent back out unchanged on the next flush.
- **Visible queue-full failure (`QueueFullError`).** Both the file-size cap
  (`max_bytes`) and the in-memory `max_queue_size` raise `QueueFullError`
  instead of silently dropping events. The client propagates the failure
  rather than masking it as success.
- **Selective ack for mixed batches.** When the server accepts some events
  and rejects others, only the rejected events remain on the queue. Accepted
  UUIDs are dropped; rejected ones survive and are retried on the next flush.
  Previously, a partial rejection put the whole batch back on the queue.

### API and defaults

- No API breakage. The default queue storage is still `MemoryQueueStorage`;
  the default `max_queue_size` is still 1000.
- Opt in with `queue={"storage": FileQueueStorage("/var/lib/custd/events.json", max_bytes=10*1024*1024)}`
  or, equivalently, `queue={"path": "/var/lib/custd/events.json", "max_bytes": ...}`.
- The SDK still rejects a non-positive `max_queue_size` at construction time.

### Scope per SDK (intentional, this release)

| SDK | Queue storage in v1.8.7 |
| --- | --- |
| Go (`sdk-go`) | in-memory (`BatchQueue`) |
| TypeScript (`sdk-js`) | in-memory (`BatchingQueue`) |
| Python (`sdk-python`) | in-memory default; opt-in `FileQueueStorage` (durable + selective ack) |
| PHP (`sdk-php`) | `FileQueueStore` (own implementation, unchanged) |
| Laravel | via PHP SDK |
| WordPress | via PHP SDK defaults |

The durable + selective-ack implementation is Python-only for v1.8.7. The
shared SDK rule "SDK functionality belongs in this repository" still applies;
future SDKs that want a durable queue will follow the Python file-backed
shape, but this release ships the durable queue as a Python-only capability
rather than splitting the milestone into per-language queues.

### Distribution

The Python SDK continues to be installed via `git+https` (subdirectory), not
PyPI, for v1.8.7. No new mirror is opened for the Python package, and the
existing `release-mirrors.yml` subtree split is unchanged (it splits
`laravel-package`, `wordpress-plugin`, and `sdk-go` to their mirror repos; no
Python mirror).

```bash
pip install "custd-sdk @ git+https://github.com/haakco/custd-sdk.git@v1.8.7#subdirectory=sdk-python"
```
