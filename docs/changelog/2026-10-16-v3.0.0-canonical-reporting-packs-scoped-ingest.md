# v3.0.0 — Canonical reporting packs and scoped ingest

Status: prepared locally; tag, publication and release-mirror verification pending.

This release replaces the Go reporting-pack shapes with the canonical contract and brings PHP and
Python onto the same contract, so a pack that round-trips in one SDK now round-trips in all four.

## Breaking

- Go: `Pack`, `PackMetric` and `PackDimension` are reshaped to the canonical reporting-pack
  contract. `PackDashboard` is removed; dashboards use the canonical definition. No aliases are kept.
- Go: the module path is `github.com/haakco/custd-sdk-go/v3`. Consumers must update their import
  path; the existing `/v2` releases stay available for consumers that have not migrated.
- PHP and Python: `ExecutiveReportDefinition` gains the required executive-recipe fields `recipe`,
  `primaryWidgetKey`, `primaryMetricKey`, `primaryLabel`, `primaryUnit` and `scopeLabel`.
- PHP and Python: accounting `rounding` is the `RoundingPolicy` object (`mode`, `decimalPlaces`)
  with the closed mode union `half_up`, `half_even`, `down` and `up`, instead of a plain string.
- `laravel-package`, `wordpress-plugin` and `sdk-react` now require the 3.x line.

## Added

- Data-scope and data-scope-resource management with explicit human and machine grants, exposed as
  `dataScopes`, `Admin.DataScopes` and `admin.data_scopes`.
- Parser presets, create, update, delete and bounded preview.
- Reporting-pack setup templates with typed list and bind operations.
- Analytics log filters for `severity`, `service`, `subClient` and `resource`.
- Declarative raw source targets with per-record acceptance. The route always answers `202`, so the
  status alone is not success.
- PHP: the `http_client` callable may declare a fourth `array<string, string> $headers` argument on
  the raw path. A three-parameter callback cannot observe the parser binding.
- Python: the transport accepts `EventEnvelope | bytes` and compresses only JSON events, so raw
  uploads are sent verbatim.

## Compatibility

- A raw `202` body must be an object carrying a boolean `success` and non-negative integer
  `processed` and `failed`. Missing, null or wrong-typed fields are rejected rather than defaulted.
- A raw transport failure, an unusable acceptance body or a retryable status is an unknown
  acceptance: the request may or may not have landed. Each SDK surfaces a typed
  ambiguous-acceptance error that recommends no replay, and never retries the raw POST.
- Client-side validation stays shape-only for codes, closed unions and UUIDs. Custd remains the
  authority on registration, grants and record selection.

## Toolchain

- The Go module requires Go 1.27.2. `golangci-lint` is pinned to 2.14.0, whose
  `golang.org/x/tools` understands Go 1.27 export data; 2.13.2 stops one export-data version short.

The shared version and SDK identity constants are `3.0.0`. Consumers must use the published GitHub
release once its mirrors are verified, not a local filesystem replacement.
