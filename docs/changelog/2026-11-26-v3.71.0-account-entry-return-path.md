# v3.71.0 — account entry with a way back, in every SDK

Hosted account settings now links back to the page an application chooses. Needs Custd `1.7.146` or later.

## Changed

| Operation | Go | TypeScript | Python | PHP | Rust |
| --- | --- | --- | --- | --- | --- |
| Create app account entry | `CreateAppAccountEntry` | `createAppAccountEntry` | `CurrentAppProfileClient.create_account_entry` | `appProfile()->createAccountEntry` | `create_app_account_entry` |

- **Return path:** every SDK takes an optional return path, a fixed page on the application origin such as
  `/mine`. It must start with `/`, has no fragment, backslash or control character, and is at most 512 bytes.
  Without one, the back link opens the application's home. Never pass the current URL: apps keep link tokens in
  paths and fragments.
- **New in Python, PHP and Rust:** account entry was Go and TypeScript only.

## Browser apps

- `openAppAccountSettings` (`@haakco/custd-sdk/browser`) asks for a ticket from the page and opens hosted
  settings in the same tab through a native form post. Custd `1.7.146` answers the browser preflight for the
  page's own origin, without credentials.
- `CustdAccountMenuItem` (`@haakco/custd-react`) is now a button built on it. It takes `issuer`, an
  `accessToken` getter, an optional `returnPath` and `onError`.

## Removed

- `appAccountNavigation`, `AppAccountNavigation` and `AppAccountNavigationConfig`. The plain settings link they
  built carried no way back to the app; use account entry instead.
