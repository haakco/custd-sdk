# v3.1.0 — Company identity and entitlement additions on the v3 line

Status: `v3.1.0` is tagged and pushed to `main`. The release-mirror workflow run `38938930307` was
still queued for a runner at handoff, so mirror, Verdaccio and Packagist publication is **not yet
verified** — check that run before treating the release as delivered. Custd's own consumers are still
pinned to `v3.0.0`; moving them is a separate step (run `scripts/dev/update-custd-sdk.sh v3.1.0` in
the Custd repository, which moves them together).

`v2.10.0` landed on `main` after the `v3.0.0` tag was cut, so the two releases describe different
product states. This release carries those additions onto the v3 line, so migrating to v3 does not
silently lose work. A published tag is never re-pointed, so the integration ships as a new release
rather than by moving `v3.0.0`.

## Added — carried forward from v2.10.0

- `companyUuid` — required nullable UUID string on the project summary and environment status. It is
  the persisted, immutable public company identity; `null` means explicitly unbound, and it is never
  inferred from a slug, an email, a membership or the caller's own company.
- `audienceEntitlementMode` — required on project and environment creation, with the named values
  `organisation_membership` and `explicit_grants`. It is immutable after creation, so a deny can never
  revert to permissive.
- `bindProjectCompany` / `BindProjectCompany` / `bind_project_company` — binds an explicitly unbound
  historical project to the authenticated human owner's company. It is the actionable step a
  `company_binding_required` refusal names; a machine credential and a foreign rebind are refused, and
  repeating it for the same company is safe.
- `acceptedPrincipalId` — nullable UUID string on invitation reads and the issuance replay receipt,
  taken only from Custd's recorded acceptance linkage. Absent or `null` means unavailable, including
  for historical accepted invitations.
- `CheckApplicationAuthority` (Go) and `checkApplicationAuthority` (PHP) — the application's online
  authority decision, sent with the application credential alone. An HTTP 200 that denies stays a
  denial.

## Fixed — carried forward

- PHP: the workflow-timing batch observation list is declared with its own type.

## Unchanged

The `v3.0.0` breaking changes stand exactly as published: the canonical reporting-pack contract for
Go, PHP, Python and JS, the `/v3` Go module path, and accounting `rounding` as the `RoundingPolicy`
object. Its migration list is in `2026-10-16-v3.0.0-canonical-reporting-packs-scoped-ingest.md`.

The shared version and SDK identity constants are `3.1.0`. Consumers must use the published GitHub
release once its mirrors are verified, not a local filesystem replacement.
