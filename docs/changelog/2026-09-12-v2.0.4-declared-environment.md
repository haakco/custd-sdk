# v2.0.4 Declared environment and producer environment updates

Every SDK can now declare which environment an event came from, and each
producer can have its authenticated environment changed after provisioning.

- New `environment` option on the client configuration (Go `ClientConfig`,
  JavaScript `ClientConfig` and `BrowserTrackerConfig`, Python `CustdClient`,
  PHP client options) and on the event envelope itself. The event's declaration
  wins over the process default. The value is sent as the reserved
  `custd.environment` label, which the SDKs still reject when written by hand
  through the generic label map.
- Declarations are validated locally: lowercase letters, digits and hyphens, at
  most 32 characters, and `unclassified` is reserved for Custd.
- New `updateEnvironment` / `update_environment` / `updateProducerEnvironment`
  and `client.provisioning.producers.updateEnvironment` producer operations for
  Go, JavaScript, Python and PHP, matching the Admin API route.
- `smoke-dev` scripts in Go, JavaScript and Python send `environment=dev` by
  default, overridable with `CUSTD_DEV_ENVIRONMENT`.

One credential serves every environment: declaring one is not a provisioning
step, and a tenant that restricts a credential to a set of environments rejects
anything outside that set with the value named.
